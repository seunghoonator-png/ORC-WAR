## 1. 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | ORC-WAR (가칭) |
| 장르 | 제로 플레이어(Zero-Player) 대규모 전투 시뮬레이션 |
| 시점/그래픽 | 탑뷰(Top-down) 2D, 미니멀 스프라이트 (참고: 『대장님, 오크가 몰려옵니다』) |
| 규모 | 양측 합산 최대 **300,000 유닛** 동시 시뮬레이션 |
| 플랫폼 | Windows 단독 실행파일 (단일 .exe, 설치 불필요) |
| 핵심 컨셉 | 유저는 **설정만** 한다 — 맵, 양측 병력 구성, 배치를 정하고 시작하면 전투는 끝까지 자동으로 진행된다 |

### 1.1 디자인 철학: "밸런스가 아니라 현실"

일반적인 게임 밸런싱(가위바위보식 상성 수치 조정)을 하지 않는다.
대신 냉병기 전투의 **실질적인 강함을 있는 그대로** 시뮬레이션 규칙으로 표현한다.

- 중기병 돌격은 대비 안 된 보병 전열을 **말 그대로 갈아버린다.**
- 그러나 자리 잡은 장창 방진에 정면 돌격한 기병은 **말과 함께 꼬치가 된다.**
- 화살비는 방패 없는 밀집 병력에 치명적이지만, 대형 방패를 든 중보병에겐 소모전일 뿐이다.
- 성벽 위의 궁수 1천 명은 평지의 궁수 1천 명보다 몇 배 가치가 있다.
- 그리고 무엇보다 — **압도적인 머릿수는 그 자체로 폭력이다.** 수적 우세를 인위적으로 보정하지 않는다.

고증(특정 시대/국가 재현)은 요구하지 않는다. "냉병기 시대에 대략 그럴듯한 물리·전술적 결과"가 기준이다.

### 3.3 방어측 전용 요소 (공성전 맵)

- **성벽 배치**: 방어측 보병/궁수/석궁수는 성벽 위에 배치 가능. 고소 보너스 적용(§5.4).
- **낙하물(바위·끓는 기름)**: 성벽 구간별 비축량 설정. 성벽 바로 아래 등반/파성추 병력에 광역 대미지.
- **성문 수비**: 성문 안쪽 대기 병력은 성문 파괴 즉시 돌파구에서 교전.

## 4. "현실적 강함" 시뮬레이션 규칙

밸런스 수치가 아니라 **규칙**으로 강함을 표현한다.

### 4.1 기병 돌격 충격 (Charge Impact)
- 일정 거리(20m+) 가속 후 접촉 시: `충격 대미지 = 기본공격 × (1 + 속도 × 질량 × 0.15)` — 중기병 풀차지 기준 약 4~5배.
- 접촉한 적을 **밀쳐내고 진형을 관통**한다(넉백 + 전도 상태 1.5초, 전도 중 방어 0).
- 돌격 관성은 3~4열 관통 후 소진 → 이후 일반 근접전. **멈춘 기병은 그냥 비싼 표적이다.**
- 측면·후방 돌격은 사기 타격 2배(§4.4).

### 4.2 장창 브레이스 (Pike Brace)
- 장창병이 **2초 이상 정지 + 적 기병 접근 감지** 시 자동 브레이스.
- 브레이스 정면(전방 120°)으로 돌격한 기병: 충격 대미지 무효화 + 기병이 `자기 속도 × 질량` 비례 반사 대미지(풀차지 중기병 즉사권).
- 이동 중이거나 측·후방을 잡힌 장창병은 보너스 없음 — **장창은 자리를 지킬 때만 벽이다.**

### 4.3 원거리 사격
- 화살은 **개별 발사체**로 시뮬레이션(곡사 궤적, 낙하 지점 판정). 30만 전장의 "화살비"를 시각 그대로 재현.
- 명중 판정: 낙하 지점 반경 내 유닛에 적용. 밀집도가 높을수록 명중률 상승 — **밀집 대형에 화살비는 실제로 재앙이다.**
- 방패: 정면 입사 화살 60% 차단(검방 보병). 후방·수직 낙하는 차단률 절반.
- 관통: `대미지 × (1 - 방어감쇄)`에 더해 석궁·중량 병기는 감쇄 일부 무시.
- 아군 오사 존재: 아군 머리 위로 쏘는 곡사는 소량의 오폭 확률. 투석기는 광역이라 오사가 진짜 아프다.

### 4.4 사기 및 패주 (Morale & Rout)
- 유닛별 사기 0~100. 감소 요인: 주변 아군 사망(반경 내 사망 밀도), 측면/후방 피격, 아군 전체 손실률, 인접 아군 패주(전염), 기병 돌격 피격, 성벽 붕괴 목격(방어측).
- 회복 요인: 주변 아군 다수, 교전 우세, 고지·성벽 점유.
- 사기 0 → **패주**: 무기를 버리고 맵 가장자리로 도주. 전투 불능, 적 추격에 무저항으로 학살당함.
- 패주는 전염된다 → 실제 고대 전투처럼 **한쪽 날개 붕괴 → 연쇄 붕괴 → 학살전** 패턴이 자연 발생한다.
- 옵션: "사기 OFF" 토글(전멸까지 싸우는 순수 소모전 모드).

### 4.5 승리 조건
- 야전: 한쪽의 전멸 또는 전원 패주.
- 공성전: 공격측이 성 중앙 목표 구역 점령(일정 수 유닛 N초 유지) 또는 방어군 전멸/붕괴. 방어측은 공격군 전멸/붕괴 시 승리.

## 5. 맵 설계

맵 크기: 기본 3km × 3km 상당(30만 유닛 수용). 타일 기반 지형 + 벡터 장애물.

### 5.1 평지 (Plains)
- 기본 개활지. 순수 물량·병종 조합 대결.
- **장애물 옵션** (체크박스, 랜덤 시드): 강(도하 가능한 여울 2~3곳, 도하 중 이속 50%·방어 불리), 숲(기병 돌격 불가·이속 감소·원거리 차단), 바위 지대(통행 불가 덩어리).

### 5.2 언덕 (Hills)
- 중앙 또는 한쪽에 완만한 언덕. 방어측이 고지 선점 배치 가능.
- 고지 효과: 사거리 +20%, 내리막 돌격 충격 보너스, 오르막 이속 -25%.

### 5.3 산악 (Mountain)
- 통행 불가 절벽 + 좁은 협곡 통로 2~3개. 자연 초크포인트.
- 소수 정예가 협곡 입구에서 물량을 막아내는 "테르모필레" 상황 재현 가능.

### 5.4 공성전 (Castle)
- 방어측: 성벽(사각 성곽, 구간별 HP), 성문 1~2개(HP 목표물), **해자**, 성내 광장·중앙 목표 구역.
- **해자**: 보병·기병 통행 불가. 성문 앞 다리로만 접근 → 공격측은 자동으로 "다리 정면 강행 / 사다리·공성탑 구간(해자 없는 면 또는 좁은 구간)"으로 병력 분산.
- **성벽 위 전투**: 성벽은 별도 통행 레이어. 지상↔성벽 연결은 사다리/공성탑/계단(성 내부)뿐. 성벽 위 유닛은 지상 근접 공격을 받지 않고, 흉벽 뒤에서 사격 시 피격 -50%.
- **성벽 파괴**: 투석기로 구간 HP 소진 시 붕괴 → 잔해 경사로가 생겨 지상 병력 통행 가능(이속 감소). 붕괴 시 그 위의 유닛 사망 + 방어측 광역 사기 타격.
- **성문 돌파**: 파성추(전용, 빠름) 또는 보병 다수 난타(매우 느림). 파괴 시 병목 돌파구 → 좁은 문에서의 학살전.
- 고소 보너스: 성벽 위 사격은 사거리 +30%, 위에서 아래 대미지 +20%.

## 6. 유닛 AI (개입 없는 자동 전투)

전략 조작이 없으므로 AI는 단순하고 결정적으로:

1. **대목표(사이드 단위)**: 공격측 = 전방 적 집단/성문·성벽 목표로 전진. 방어측 = 배치 지점 유지, 적 접근 시 요격(공성전은 성벽/돌파구 방어 우선순위 큐).
2. **병종 기질(하드코딩된 교리)**:
   - 근접 보병: 최근접 적에게 전진·교전. 밀집 유지.
   - 궁수/석궁수: 사거리 내 최대 밀집 지점 사격. 적 근접 시 후퇴 시도(뒤가 막히면 근접전).
   - 중기병: 적 원거리/측면 노출 집단 우선 돌격 → 관통 → 이탈 → 재돌격 사이클.
   - 경기병: 외곽 우회, 패주병·공성병기·후방 궁수 사냥.
   - 궁기병: 거리 유지 카이팅.
   - 공성병기: 지정 목표(성문/성벽 구간)로 직행, 보병 호위 무리와 동행.
3. **국소 행동**: 분리(밀집 압력), 정렬, 목표 추종 — 보이드식 3규칙 + 전장 압력 모델. "오크가 몰려옵니다"류의 **꾸역꾸역 밀려드는 군중 움직임**이 여기서 나온다.

## 7. 그래픽 & 연출

- **유닛**: 8~12px 미니 스프라이트, 병종별 실루엣(창은 길게, 기병은 말+기수), 팀 컬러 틴트(적/청 + 커스텀). 애니메이션은 2~4프레임(까딱임·방향 플립)으로 최소화 — 물량이 곧 비주얼이다.
- **시체·핏자국**: 사망 지점에 데칼로 영구 누적(별도 정적 텍스처에 베이크 → 렌더 비용 0에 수렴). 전투가 끝나면 **맵 자체가 전투 기록**이 된다.
- **발사체**: 화살비(수만 발 동시 궤적), 투석 포물선 + 착탄 먼지, 발리스타 관통선.
- **구조물**: 성벽 붕괴 파편, 성문 파쇄, 불타는 공성탑.
- **카메라**: 자유 이동 + 휠 줌. 최대 줌아웃 시 전 전장 조망(유닛은 점으로 LOD 전환), 최대 줌인 시 개별 교전 관찰.
- **HUD**: 상단 양측 잔존/패주/사망 게이지 바, 배속 컨트롤, 미니맵(병력 밀도 히트맵).

## 8. 기술 설계

### 8.1 스택 선정

| 후보 | 평가 |
|---|---|
| **Rust + macroquad/wgpu** ✅ **채택** | 단일 정적 .exe(수 MB), 300k 유닛 CPU 시뮬 여유, GPU 인스턴싱 렌더, 크로스 컴파일로 리눅스 개발 → Windows 빌드 용이 |
| C++ + SDL2 | 성능 동급이나 빌드/의존성 관리 부담 |
| Unity (DOTS) | 가능하지만 단일 exe 아님(폴더 배포), 런타임 무거움 |
| Godot / Python | 30만 유닛 개별 시뮬에 부적합 |

### 8.2 30만 유닛 성능 전략 (목표: 시뮬 20Hz 고정 스텝 + 렌더 60fps)

- **데이터 지향(SoA)**: 유닛 = 구조체 배열이 아닌 배열들의 구조(위치/속도/HP/상태 각각 연속 배열). 캐시 적중률 극대화.
- **공간 해시 그리드**: 2~4m 셀. 이웃 탐색·충돌·근접 판정 전부 셀 단위.
- **플로우 필드 경로탐색**: 유닛별 A* 금지. 목표 지점당 플로우 필드 1장을 수백 ms 주기로 갱신, 30만 유닛이 공유. 지형 비용(숲/여울/경사) 반영.
- **멀티스레딩**: rayon으로 시뮬 페이즈 병렬화(이동/전투/사기/발사체 각 페이즈 내 데이터 병렬).
- **시뮬 LOD**: 교전 반경 밖 유닛은 5Hz 갱신(이동만), 교전 유닛만 20Hz 풀 시뮬.
- **렌더**: 텍스처 아틀라스 1장 + GPU 인스턴싱 → 병종당 드로우콜 1개. 줌아웃 시 포인트 스프라이트 전환.
- **발사체 풀링**: 화살 최대 동시 20만 발 고정 풀.
- 목표 사양: 8코어 데스크톱 CPU + GTX 1060급에서 30만 유닛 실용 프레임. (초과 시 배속 대신 시뮬이 느려지는 우아한 저하)

### 8.3 결정론
- 고정 스텝 + 시드 고정 → 같은 설정과 시드는 항상 같은 전투 결과. 리플레이·검증·"설정 공유" 기능의 기반.

### 8.4 배포
- `cargo build --release --target x86_64-pc-windows-gnu` → 단일 `orc-war.exe`. 에셋은 exe에 임베드(include_bytes). 설치·런타임 의존성 없음.

## 10. 리스크 및 결정 필요 사항

1. **성능 상한**: 30만은 공격적 목표. M1에서 실측 후, 미달 시 "시뮬 LOD 강화"가 1순위 대응(유닛 수 축소는 최후 수단).
2. **성벽 위 표현**: 탑뷰 2D에서 높이는 레이어+그림자로 표현. 시각적 혼동을 줄이기 위해 성벽 유닛은 약간 확대+테두리 처리 예정.
3. **배치 UI 깊이**: 초기엔 프리셋(전열 보병/후열 궁수/양익 기병 등) 중심, 드래그 사각형 배치는 M5에서 판단.
4. **사기 시스템**: 현실성의 핵심이지만 "끝까지 싸우는 그림"을 원할 수도 있어 ON/OFF 토글로 제공.
